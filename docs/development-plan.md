# 開発計画

## 目標と参照先

[要件定義書](requirements.md) の受入条件を満たすWindows向けCLIを、Goの標準ライブラリで実装します。この計画は実装順序と検証の進め方を管理し、製品仕様は要件定義書を正本とします。開発・検証の入口は [README](../README.md)、変更時の制約は [AGENTS.md](../AGENTS.md) に記載します。

M1の開発基盤、M2の情報収集に続き、M3の記録比較を実装・検証しました。対応形式とJSONの具体的な契約は [収集方式と記録形式](scan-format.md)、比較の取り決めは [記録比較](diff-format.md) を参照してください。M4の製品全体の受入確認は後続の作業です。

## 検証を追加する場所

M2では、導入情報を読む処理、PATHを探索する処理、JSONを出力・保存する処理の振る舞いを、それぞれ実装に隣接するテストで確認します。M3では、同じ事実の順序違いと意味のある変更を区別するテストを追加します。受入条件に関係のない件数や網羅率を目標にしません。

模擬データには空白・日本語を含むパス、利用者単位と共通の同名パッケージ、複数の公開コマンドを含めます。CLIに見せかけたファイルを置き、それが実行されないことも確認します。権限による読取失敗は、実際の読取制限と、読み取り境界から失敗を返すテストを使い分けます。

環境変数の変更はテストのプロセス内に限定し、終了時に元へ戻します。実際の導入先・PATH設定・プロファイル・認証情報は変更しません。

## 調査で確定した事項と残る制約

| 事項 | 影響 | 解消方法・時期 |
| --- | --- | --- |
| Scoopの導入先と導入済み情報の形式 | 導入版・公開コマンド・shimの根拠を誤る可能性がある | 公式実装を確認し、保存済みマニフェスト・導入時の構成・exe型shimに対応。スクリプト型shim、env_add_pathの列挙、no_junctionは未対応として明示 |
| WindowsのPATHと拡張子の探索規則 | PowerShell全体の名前解決と取り違える可能性がある | 公式資料・実装でPATH順と.ps1・PATHEXT順を確認し、模擬環境で検証済み。PowerShellの関数等は対象外 |
| JSON内の識別方法と配列の順序 | 異なる事実を同一視する可能性がある | `schema_version: 1` の型、識別子、優先順位の数値と比較処理を実装・文書化・検証済み |
| Windows ARM64の対応と配布経路 | 未検証の実行環境を対応済みにするおそれがある | 今回は利用可能なWindows AMD64で開発基盤を検証する。追加の構成と公開方法は配布の依頼時に決める |

## M2の検証結果

- 要件7章の5・6・9について、対象を起動しないこと、調査前後のファイルと環境変数の一致、破損JSON、読み取り境界から返す権限エラー、未対応の定義・shim、余分なメタデータの非出力、JSONオブジェクト1件と診断の分離を確認しました。
