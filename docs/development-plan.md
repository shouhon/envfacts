# 開発計画

## 目標と参照先

[要件定義書](requirements.md) の受入条件を満たすWindows向けCLIを、Goの標準ライブラリで実装します。この計画は実装順序と検証の進め方を管理し、製品仕様は要件定義書を正本とします。開発・検証の入口は [README](../README.md)、変更時の制約は [AGENTS.md](../AGENTS.md) に記載します。

今回の依頼範囲はM1のセットアップです。M2以降は後続の製品実装として残します。

## 検証を追加する場所

M2では、導入情報を読む処理、PATHを探索する処理、JSONを出力・保存する処理の振る舞いを、それぞれ実装に隣接するテストで確認します。M3では、同じ事実の順序違いと意味のある変更を区別するテストを追加します。受入条件に関係のない件数や網羅率を目標にしません。

模擬データには空白・日本語を含むパス、利用者単位と共通の同名パッケージ、複数の公開コマンドを含めます。CLIに見せかけたファイルを置き、それが実行されないことも確認します。権限による読取失敗は、実際の読取制限と、読み取り境界から失敗を返すテストを使い分けます。

環境変数の変更はテストのプロセス内に限定し、終了時に元へ戻します。実際の導入先・PATH設定・プロファイル・認証情報は変更しません。

## 着手前に解消する事項

| 事項 | 影響 | 解消方法・時期 |
| --- | --- | --- |
| Scoopの導入先と導入済み情報の形式 | 導入版・公開コマンド・shimの根拠を誤る可能性がある | M2の前にScoopの公式実装を確認し、読み取るファイルと対応形式を明記する。最新版のbucket情報で補わない |
| WindowsのPATHと拡張子の探索規則 | PowerShell全体の名前解決と取り違える可能性がある | M2の前に公式資料で実行ファイルの探索範囲を確定し、PATHと拡張子の優先順を模擬環境で検証する |
| JSON内の識別方法と配列の順序 | M3で異なる事実を同一視する可能性がある | M2で `schema_version: 1` の記録例と照合規則を確定する。優先順は配列の偶然の順序に依存させない |
| Windows ARM64の対応と配布経路 | 未検証の実行環境を対応済みにするおそれがある | 今回は利用可能なWindows AMD64で開発基盤を検証する。追加の構成と公開方法は配布の依頼時に決める |

## M1の検証結果

2026年10月22日、Windows AMD64・Go 1.27.3で確認しました。

- `pwsh -NoProfile -File ./scripts/check.ps1` が成功しました。整形、静的検査、テスト、ビルド、実行ファイルの起動を確認しています。
- ビルドした実行ファイルで、`--help` と `--version` が終了コード `0` で標準出力だけに出力し、不正な引数が終了コード `64` で標準エラーだけに説明を出すことを別途確認しました。
- CLI版番号は未設定から初回の `0.1.0` を新設し、`--version` の表示が `internal/cli/version.go` の正本と一致することを確認しました。JSON形式の実装は今回の対象外です。
- 要件定義書は移動前後のSHA-256が一致し、移動元にファイルが残っていないことを確認しました。本文と文書版は維持しています。
- 外部のGoモジュールは取得せず、検証中はGoの自動取得を無効にしました。開発用キャッシュと一時ファイルはGit管理対象外の `.cache/` 内に置きました。
- 作業開始時点でGitリポジトリと追跡先はありません。コミット・プッシュは行っていません。
