# envfacts 要件定義書

- 文書版: 1.0
- 状態: 初版・未実装
- 目的: ローカル環境のCLIについて、導入情報とコマンドの名前解決結果を集約し、LLMが扱える形式で報告する。

## 1. 利用場面と完成条件

CLIを追加した後や、新しいLLMの作業セッションを始める際に使う。Scoopの導入情報とPATHを調べ、何が導入されているか、どの実体が優先されるか、何が未確認かを1回の調査で把握できることを完成条件とする。

「導入情報がある」「PATHから見つかる」「実際に起動できる」を別の事実として扱う。初版は対象CLIを実行しないため、起動・認証・ネットワーク接続・サンドボックス内での動作は未確認とする。

## 2. 初版の対象

- Windows 11・PowerShellで利用する非対話型CLIとする。
- Scoopの利用者単位・全利用者共通の導入先と、現在のプロセスのPATHを対象にする。
- Scoopの導入先は環境変数などの明示設定を優先し、標準の導入先も扱う。実際に調査した導入先を出力する。
- 初版ではWSL、コンテナー、プロジェクト内の仮想環境、npm・uvなど他の管理方式の導入台帳を自動走査しない。
- 他の方式で導入されたCLIも、名前を明示すればPATH上の存在を調べられる。ただし導入元や版を推測で埋めない。
- インストール、更新、修復、PATH変更、認証確認、CLIの用途推薦、AGENTS.mdの自動更新は行わない。

## 3. コマンド

| コマンド | 要件 |
|---|---|
| envfacts scan [--command <名前> ...] [--json] [--output <ファイル>] | 現在の情報を収集する。 |
| envfacts diff --before <記録> --after <記録> [--json] | 保存済みの2つのJSON記録を比較する。再調査はしない。 |
| envfacts --help / --version | 日本語の使い方、調査範囲、版番号を表示する。 |

--command を指定した場合は、その名前だけを調べる。指定しない場合は、Scoopの導入済み情報でCLIとして公開されているコマンドを対象にする。GUIアプリや、実行コマンドを持たないパッケージも区別して記録する。

--output がある場合はJSONを指定先に保存する。既存ファイルは上書きせずエラーにする。--output がなければファイルを作成しない。記録比較に使うファイルは scan --json のリダイレクトでも作成できる。

## 4. 収集する事実

- 導入版は、導入済みの実体に対応するローカル情報から取得する。bucketにある最新版を導入版と取り違えない。
- パッケージ名と実行するコマンド名を区別する。1つのパッケージが複数のコマンドや別名を公開する場合も扱う。
- PATHの優先順に候補を列挙し、最初に見つかった実行ファイルと、後順位で隠れている同名の候補を示す。
- 現在のPATH・拡張子の規則に基づく実行ファイルの探索を行う。PowerShellの関数・エイリアス、プロファイルによる上書き、実行ポリシーの判定は初版の対象外とする。
- Scoopの呼び出し用ファイル（shim）は、解釈可能なローカル情報から参照先を確認する。不明なスクリプトを実行して実体を推測しない。
- 存在しないコマンドは not_found、版が不明な場合は null と理由を記録する。情報の不足と不存在を混同しない。
- 一部の導入情報が破損・読取不能でも、読めた結果と読めなかった範囲を分けて返す。
- 対象CLIの --version、Scoop・npm・uvの情報取得コマンドも自動実行しない。情報取得を理由にロックやキャッシュを作らない。

## 5. JSONと比較の契約

JSON表示は標準出力にオブジェクト1件を出し、診断は標準エラーに分ける。少なくとも以下の項目を持つ。

| 項目 | 内容 |
|---|---|
| schema_version / tool / command | 形式の版、envfacts、scan または diff |
| status / captured_at / coverage | 調査の状態、UTCの記録日時、調査先と対象外の範囲 |
| packages | パッケージ名、管理方式、利用者単位か共通か、導入先、導入版、根拠となるローカル情報の場所 |
| commands | 名前、resolved または not_found、優先するパス、全候補、確認できた実体、関連パッケージ、版とその根拠 |
| invocation_status | 初版では not_tested。見つかったことだけで起動成功にしない。 |
| changes | diff時の追加・削除・導入版変更・実体変更・優先順変更 |
| issues | 機械判定用の code、日本語の説明、関係する情報源 |

scanの status は complete / missing / incomplete / invalid_arguments とする。diffでは unchanged / changed / incomplete / invalid_arguments を使う。

比較では記録日時や配列の順序だけを差分にしない。同じコマンドでも、先に解決される実体が変わった場合は変更として扱う。版が不明なものを、同じ版であることが確認できたかのように表示しない。異なる調査範囲の記録では共通の範囲を明示し、全体が比較済みとは扱わない。

配列の並び順は安定させ、空白・日本語を含むパスを正しく扱う。ファイル本文、プロファイル、環境変数の全件一覧、shimの引数、取得元URLの認証情報を出力しない。

## 6. 終了コード

| 終了コード | 意味 |
|---|---|
| 0 | scanが完了し、明示した名前の不足なし。またはdiffが完了して差分なし。 |
| 1 | scanで明示したコマンドが見つからない。またはdiffで差分あり。 |
| 2 | 調査・保存・比較が不完全、記録が不正、読取不能など。 |
| 64 | 引数の誤り。 |

不完全な結果と不足・差分が併存するときは終了コード2を優先し、判明している事実は出力する。引数の誤りでも --json の指定を認識できる場合はJSONで説明する。

## 7. 受入条件

1. Scoopのパッケージ名と異なるコマンド名、複数の実行コマンド、shimを区別して報告する。
2. 利用者単位と全利用者共通の両方に導入された同名CLIを、混同せず報告する。
3. PATHに同名の実行ファイルが複数あれば、優先する候補と隠れた候補を示す。
4. 明示した未導入CLI、導入情報はあるがPATHから見つからないCLI、版が不明なCLIを区別する。
5. 調査前後で対象CLIを実行せず、環境設定、キャッシュ、ロックファイルを作成・変更しない。
6. 壊れた導入情報や読取不能な場所を、未導入や調査成功に置き換えない。
7. 同じ事実を異なる順序で保存した記録は差分なしとし、導入版・実体・PATHの優先順の変化は検出する。
8. 異なる調査範囲、未対応の schema_version、JSONの破損を適切に報告する。
9. 機密値を含む余分なメタデータを出力せず、JSONと終了コードが契約に従う。

実装時の検証は、模擬の導入先・shim・PATHを使って行う。実際のScoop導入先を検証のために書き換えない。

## 8. 版管理と実装時に決める事項

本書の初版は1.0とする。CLIは未実装のため、今回のCLI版番号の更新は対象外。実装開始時の初回CLI版は0.1.0、JSON形式は schema_version: 1 とし、版番号の正本を1か所に定めて --version と配布物を一致させる。

実装言語、配布方法、Scoopの導入済み情報を読む内部方式は実装時に決める。確認できない形式を推測で解釈する代わりに、その情報源を未対応として報告する。
